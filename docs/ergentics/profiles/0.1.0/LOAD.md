# Load a profile with a selected corpus

1. The caller supplies trusted external receipt locators and expected manifest hashes for this package and Ergentics Agents v0.1.0. Verify the helper against the package manifest before executing it; a helper cannot establish its own bootstrap trust. Resolve the current policy through the receiving host's authorized Alignment binding. Do not infer authority from a hash or review label.
2. Create a current request using the [contract](CONTRACTS.md). Supply absolute roots at this boundary, exact selection IDs/versions/hashes, actual purpose/recipient/processing route, requested model/effort/context/tools and finite budgets. Use the current task's input and output scope. Model names are dispatch choices; the packet helper does not validate their availability or select alternatives.
3. Run `ruby scripts/profile_packet.rb prepare --request REQUEST_PATH --request-sha256 EXPECTED_REQUEST_SHA256 --output NEW_PACKET_DIRECTORY`. The parent must exist. Output must not exist. A rejected request reports a structured cause and read ledger without emitting payload text. Failed partial output retains or restores `INCOMPLETE` where the owned directory is still accessible. Never load output from a failed invocation even if that marker could not be restored. Loading requires successful command completion as well as a complete verified receipt; this is not crash-safe storage.
4. Inspect `RECEIPT.json`, its selected entries, read ledger, generated file hashes and `NOT_PERFORMED`/`NOT_OBSERVED` execution fields. A prepared packet is not a load receipt. Completed files/directories are made read-only to reduce accidental edits, but their owner can change permissions. The caller verifies exact bytes and membership before handing any packet to a model; these modes are not tamper-proof storage or per-agent isolation.
5. For an authorized dispatch, supply the concrete packet root, expected receipt SHA, exact assignment and separate result directory. Have the recipient verify receipt/file hashes, read `READ-ME.md` and the named profile/Agent/policy/corpus files, and report those actual reads in a separate observation. Keep requested model/effort, visible returned labels, exact serving-build unknowns and inherited context separate.
6. Preserve the first result and failures. Inspect the actual result before marking any behavior qualified. Shared filesystem access means that separate contexts/folders do not establish enforced blinding. A future run loads an explicit corpus version/selection; it does not silently inherit all past outputs.

Model execution remains with the host adapter. Budgets in the request are run requirements; the local packet helper does not supervise or enforce a hosted model's lifetime or output. Use the receiving host's actual controls and record their limits. Pure packet creation makes no inference-provider privacy or local-model claim.
