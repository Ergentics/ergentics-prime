# Codex explicit adapter

This route uses the current collaboration tool's concrete `message`, optional model/effort override, and context inheritance control. An ordinary task name is a label; it is not native role-registry activation.

Resolve availability and user/project model constraints before dispatch. A new bounded evaluation can request `fork_turns: none` plus the exact supported model/effort. This limits inherited conversation context; it does not isolate the shared filesystem or prove independent backend identity. Existing contexts must record their actual known inheritance instead of claiming freshness.

Supply the verified prepared packet root and receipt hash, selected profile ID/version, assignment, allowed input/output locations and stop condition. Ask for a separate load observation and the task result. Do not copy corpus payload into developer instructions; keep attributed corpus data distinguishable from the actual instructions/authority. Record what was actually read and inspect the returned work.

Packet preparation never dispatches a model. This adapter is an explicit instruction handoff convention; no global Codex configuration, automatic discovery, native agent_type registration or provider-data setting is changed. Native registry overlays in the Agent dependency retain their separate unqualified status.
