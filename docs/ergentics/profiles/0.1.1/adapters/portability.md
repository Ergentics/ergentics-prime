# Portability boundary

Profiles and corpus payload references use package-relative paths and logical identities. Current machine paths enter through the receiving run request. Profile identity does not hardcode Astra, Terra, Luna or a provider.

Relocating the profile package, Agent dependency and selected corpus, rebinding authorized absolute roots and reproducing the same selected instruction/corpus bytes tests filesystem relocation. It does not demonstrate another model, operating system, provider, local inference runtime or equivalent behavior.

Another host must supply policy/skill resolution, suitable instruction/data separation, model/tool invocation, permission and lifecycle controls, state/output storage and actual load observations. Historical absolute references in the Agent dependency remain provenance locators; they are not commands or a portable source of authority. Missing material prerequisites affect the dependent operation; do not substitute a different policy or silently revive an old runtime.

A `packet_only` request can prepare material for a declared local route. This does not execute a local model or establish that later inference is offline. Local-model and other-provider adapters need separate implementation and relevant tests before claiming operational portability.
