# Ergentics Profile Loader

Load the selected durable Agent and operating profile through the receiving
host's explicit instruction route. The Agent/profile packages remain separate
versioned definitions; this skill is their Codex discovery/loading adapter.
It supplies no model weights, new tool permissions or background process.

## Bind the current task

Resolve current Ergentics Alignment and receiving-project instructions, then
recover the user's actual objective, approved operations and task record.
Installation does not resume unrelated held work. Use current user direction
over old examples; only hold actions dependent on unresolved prerequisites.

Name the blocked operation for each hold. A commit hold blocks creating a
commit; a retained-runtime hold blocks that runtime's activation or qualification.
Neither prevents already-authorized read-only source/caller comparison, metadata
validation in a separately approved environment, or task evidence notes that do
not depend on the held operation. Do not ask for either hold to be lifted merely
to start such independent work. Keep the instruction to avoid Prime intake during
a synthetic load check separate from the real task's authorization afterward.

Read [the installed bindings](references/installed-bindings.json). Verify its
expected package manifests and the selected loader helper before execution.
A missing or changed dependency stops that load; do not silently fall back to
a historical renderer, different version or other source root. Installation
facts come from the external installation receipt, not this candidate's paths.

The stable IDs are `ergentics_swift_c` and `ergentics_cpp`. Keep the selected
identity/version independent of requested model, effort and host. A request
for two profiles means two explicitly bound roles; it does not prove distinct
serving builds. Read only the selected profile and relevant package guidance.

## Prepare and load

Follow the installed profile package's LOAD.md and CONTRACTS.md. Supply a new
run ID, actual assignment/authority, purpose, source/input references, requested
model/effort/context/tools, recipient/processing route, finite budgets and a
separate result directory. Extensions are inert references; verify task inputs
explicitly before using them. Project language/runtime rules take precedence
over a role's general baseline.

Select only relevant accepted corpus entries by exact ID/version/hash. The
installed corpus includes a phase-scoped observation lesson; apply it when
reporting loads. Do not pull whole prior outputs, histories, held-out answers,
dependency environments or credential paths into context. Corpus references
and permission/review labels do not authenticate authority.

Run the verified Ruby packet helper for preparation when authorized. Require
successful completion, expected receipt identity and exact member/hash checks
before dispatch. Never load a failed/partial packet, even if INCOMPLETE is
missing. Keep task output outside the installed release and prepared packet.

For an authorized host dispatch, pass the exact packet root, receipt hash,
assignment, allowed intake/output paths and stop condition. The recipient
reads the staged profile, Agent/common instructions, policy and selected
corpus, and writes a separate observation using [the observation template](assets/load-observation.json).
Review actual results before qualifying behavior. This explicit route is not
native `agent_type` registration or proof of automatic role activation.

## Keep observations and lessons durable

A helper's no-dispatch receipt describes preparation. If a later hosted agent
reads the packet and answers, record that hosted activity. Unknown serving
identity does not erase an observed response. Conversely, preparation alone
does not prove loading. Keep requested settings, visible labels, actual reads,
native execution and provider-control evidence separate. Use the template's
standard schema label; populate observations from evidence, never from wishes.

Preserve original responses and failures before corrections or synthesis.
Shared workspace access is not enforced blinding; owner-reversible file modes
are not access isolation. Hosted reads enter the hosting provider's processing
context; this skill does not establish retention/training controls.

Promote selected attributed lessons only after exact positive and golden-
negative evidence is reviewed. Auto Harvest may package that focused lesson
under its own authorized bounded control; loading this skill starts no harvest.
Keep package/profile/Agent/policy/corpus versions separate and preserve issued
releases. See [lineage and extension](references/lineage-and-extension.md).

For changes to this skill, use [the shared metadata procedure](references/metadata-validation.md)
and the declared validation dependency. Metadata, installation, observed
loading and application readiness remain different results.
