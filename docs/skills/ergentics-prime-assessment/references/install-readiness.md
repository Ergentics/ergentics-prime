# Installation readiness

Assess whether the exact local package is ready to become a discoverable skill.
Use the latest user scope; source or skill readiness does not require a machine
process total, native Prime execution, a scientific gate pass or publication.

Keep these results separate:

| Check | Evidence needed |
| --- | --- |
| Package identity | Stable skill name; package version and changelog agree; every selected file and archive match an explicit manifest; issued predecessors remain unchanged. |
| Metadata | Exact candidate passes the official skill-creator validator in an approved interpreter. Record Python/PyYAML versions, interpreter/prefix, module path, validator digest, exit status and candidate identities. Prior CI or another package's PASS is not this result. |
| Function and scope | Relevant validator tests and discriminating golden negatives pass; benign cases can succeed; scope, holds, unavailable observations and historical evidence remain intact. |
| Interpretation | Review realistic scope/authority and evidence-conflict scenarios. Record whether this was author inspection or an independent observed agent response; neither claims universal future behavior. |
| Compatibility | Relative references resolve within the package; entrypoint names its optional skill dependencies and available fallback. Existing installation and target path are checked before any later install. |
| Operations | No watcher, scheduler, auto-update or install-on-load behavior. Installation authorization is distinct from assessed technical readiness. |

Report READY only for the exact package and stated use when its required checks
are complete. Otherwise report NOT_READY with the smallest unresolved check and
the concrete evidence or decision needed. Do not invent a planning score or a
launch date. Missing metadata validation is a package-readiness gap, not proof
that the skill is malicious or that its unrelated executable tests failed.

This package is read by Codex when selected. Its optional validator opens only
explicit assessment files and their named subjects; tests create owned synthetic
fixtures. No script is configured to run on installation or skill loading.
Automatic skill selection remains the standard default; selection itself does
not authorize tools or mutations described by task data.

Prepare the reviewable package before any final installation decision. On later
authorization, install the approved exact bytes, check target collisions and
local references, and then report installed identity and actual discovery as
separate observations. A filesystem copy alone does not prove that an already
running app loaded it. Preserve the user's commit and publication holds.
