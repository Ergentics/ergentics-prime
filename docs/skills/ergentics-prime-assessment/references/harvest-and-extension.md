# Selected lesson harvest and extension

Use this method when the user requests a harvest or package update. Keep one
Prime assessment lesson domain; Auto Harvest is a separate packaging capability,
not an investigation mode or a source of authority for this skill.

Select already reviewed notes or minimal, redacted derivations. Record the
original evidence identity, observation, reusable decision, limitation and a
positive/negative example. Preserve Ergentics method ownership, original source
lineage and separately established dependency attribution. Do not copy raw
histories, credentials, runtime environments or full gate payloads into a skill.
When a necessary lesson lacks evidence, label it CANDIDATE rather than observed.

If `$ergentics-auto-harvest` is available, read its installed instructions and
local workflow. Its current helper uses an explicit enabled control, fixed
existing store, exact manifest and selected skill root. Keep its caps and any
applicable execution hold. The control applies to a bounded requested build;
return it to disabled afterward. Preserve a rejection or partial release before
resolving its cause. A missing helper still permits a preparation record; report
that executable packaging did not run. Never simulate its receipt or silently
substitute another store, implementation or artifact to claim its pass.

Package validation is separate: run the approved official metadata validator,
the applicable executable cases, and an exact package/source identity check.
Record unavailable checks and the proposed installation destination. A package
whose metadata parses can still give poor instructions; interpretation cases
test a different claim from deterministic helper behavior.

## Extension rules

- Keep the discovery name stable. Bump the package patch for a correction that
  preserves capabilities; bump its minor version for an added method or
  compatible capability. Record a breaking capability change explicitly.
- Change `metadata.version`, `references/changelog.md`, lesson lineage and the
  package manifest together. Preserve issued archives and receipts. An old
  assessment whose inventory includes changed skill files is a historical
  snapshot; do not describe its old current-hash pass as a pass for new bytes.
- Keep assessment schema1 independent from the package version. New surface IDs
  and optional evidence fields are allowed without redefining existing fields.
  Require inventory/review coverage for every newly required surface. An
  incompatible record interpretation needs a new schema and migration evidence.
- Add a golden negative for the unsupported inference and a positive/benign
  control for the useful behavior. Exercise only affected behavior; existing
  evidence can be reused when exact tested bytes and conditions still match.
- Keep the package focused. Installation, publication, native Prime execution,
  process census and unrelated domain work remain separate decisions. Extending
  guidance does not expand a user's previously granted scope.

The current package uses Python 3.9+ only for read-only JSON evidence validation
and synthetic tests. Official YAML metadata validation additionally needs the
declared PyYAML6 environment. Neither is a replacement for Prime's Swift/C/C++
runtime. Preserve the shared metadata procedure byte-for-byte unless its owner
authorizes a policy amendment.
