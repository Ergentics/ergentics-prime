# Ergentics Prime Custody

Version **0.1.0**. Ergentics, LLC owns the originating method. This is a focused
Prime extension to Research Custody, not a replacement policy or gate runner.

## Bind the decision

Recover the current user scope and Alignment policy. Identify the exact repo,
base/head/tree, intended merge destination, evidence phase and operation being
decided. Read the relevant current authority and immediate workflow caller.
Use Research Custody for protected scientific semantics and attempt authority;
this skill supplies neither. Keep Driver V2, fixture-identity V2 and HyperVisor
H1–H8 as distinct families even when labels coincide.

Before proposing a trigger, check both the workflow event/branch/job predicates
and the invoked script's accepted events, ancestry, path set, source pins and
phase requirements. A declared manual trigger can still be rejected by its
caller. An ancestor relationship need not satisfy a direct-parent requirement.

Record these separately, using the narrow observed result for each:

- trigger configured and event actually delivered;
- exact revision selected and caller admission outcome;
- checks that ran, failed or were skipped;
- current source/native qualification under the applicable family;
- commit/push/remote-SHA state and merge into the intended destination.

GitHub mergeability is not passing CI. A green source check does not qualify
a native run. Missing attempt metadata stays unknown; a run number is not an
attempt number. Consult [the record fields](references/gate-record.md) when
materializing a decision, and retain the first failure and later corrections.

## Handle a phase mismatch

Read the retained transition/restoration contract before editing a frozen gate.
Identify predecessor, terminal state, allowed next mutation, timeout/resource
restoration and any new execution opportunity. Derive current values from that
contract; the historical example's SHA, path count and timeout are not defaults.

Classify the proposed change using Research Custody. A change to protected
admission or acceptance semantics after an outcome is a protocol amendment;
prepare its exact effect for the applicable Ergentics review before applying it.
A pre-authorized restoration may already have its own allowed scope and review
conditions. Resolve those conditions without inventing another approval layer.
Do not loosen ancestry or path predicates simply to turn a known failure green.
Do not retry a governed scientific attempt automatically. Ordinary CI repair or
rerun authority is a separate, current-task question, not a universal retry ban.

Name what a hold actually blocks. Continue authorized source inspection, edits,
documentation, metadata validation and lesson packaging that do not depend on
the held operation. Preserve the distinction between an authorized change and
evidence that its execution succeeded.

## Share the reviewed lesson

Select a small attributed derivation, its original evidence locator and the
correction, then test a useful action and a discriminating golden negative for
each receiving profile. Keep evaluator answers outside profile intake. Record
actual observations and failures; two agreeing roles are not independent proof.

Use the profile loader for exact current packets. Promote only reviewed content
into a new explicitly selected corpus contribution. Packaging, preparation,
actual instruction loading, installation and native activation are separate.
An existing role does not silently inherit updated files or the whole corpus.
Requested model/effort and observed serving identity remain separate.

Use Auto Harvest only for the authorized, bounded package build. It does not
execute this skill, install a watcher, publish files or confer authority.
For versioning, source attribution, the observed Prime example and checks, read
[the extension record](references/lineage-and-extension.md). For metadata use
[the shared procedure](references/metadata-validation.md) and the declared
dependency; reuse the approved environment.
