# Native Agents workspace — Build 24

The Agents destination installs Ergentics Swift+C and Ergentics C/C++ profile
definitions v0.1.0, Prime custody method v0.1.0 and eight selected reviewed corpus
entries. The native catalog is v0.1.0. Ergentics, LLC retains policy, research and
method authority. The profile package's preparation helper is v0.1.1; logical
profile identities remain v0.1.0.

The text workspace supports local tasks, messages, readable activity, profile
and corpus inspection, and explicit prepared-task export. Ergentics Prime uses
the existing Native-300M Stage 7 experimental byte-token generation route. Its
signed helper checks, shared process admission, cancellation, 300-second timeout,
1023-byte canonical input and 1–256 generated-token bounds remain unchanged.
This checkpoint is not a qualified general instruction-following agent.
Requested hosted model labels in exported tasks do not establish a connection.

Native installation means the app has verified and made the selected definitions
available. Profile preparation, actual model instruction loading, generation,
output review and scientific qualification remain separate. The workspace
does not invoke a model until the user sends a request. Historical native gates,
private H7/H8 state, Surface and Codex package installation are separate.

## Resources and extension

`Resources/ErgenticsAgents/catalog.json` names every selected resource by path,
size and SHA-256. `Sources/ErgenticsAgentCatalogIdentity.swift` pins that catalog.
The native reader validates bounded regular files beneath the selected root and
retains verified text in memory. A source-selection resource preserves original
versions and locators; those locators are informational and never followed.
The policy file is an exact selected EA-POLICY-001 v0.4.1 snapshot, not a new
canonical authority. Bundled skill and contract text runs no scripts.

Updates require an explicit source selection and review, new catalog version
where its contract or content changes, updated hash pin and matching native
tests. Preserve stable profile IDs and authored attribution. Extend the loader's
supported versions deliberately rather than silently accepting unknown formats.
The catalog's size limits are implementation choices, not research gate rules.
Keep positive controls and golden negatives tied to the behavior they check.

Conversations, response observations and saved drafts live in the app's
dedicated ErgenticsAgentTasks storage (Application Support in the app container).
Save local draft or switch tasks to retain an unsent message. Only the current
message is sent to Prime; conversation history, selected profiles and corpus
are not supplied to this experimental model. User requests are persisted before
generation starts. Storage failure stops an owned run and keeps its observed
cleanup visible. Reopening marks unfinished observations as interrupted.
An explicit recovery preserves the original files and binds a new store for
subsequent launches. The app-lifetime workspace retains run ownership during
sidebar navigation.

These are local
application data and may contain the user's text. Screen capture, accessibility
and same-user filesystem access are not excluded by this feature. Export writes
only after an explicit save-panel choice. There is no background harvest,
watcher, collector, network client or automatic corpus promotion.

## Validation and delivery

Use the existing ErgenticsPrime Xcode scheme with its signing identity and
entitlements unchanged. Run the new ErgenticsAgentLibraryTests,
ErgenticsAgentTaskStoreTests and ErgenticsAgentsModelTests, plus relevant existing PrimePromptTests when
connecting the text runner. Compilation, synthetic controls, view rendering,
native interaction, signature validation and installed execution have distinct
evidence. Current results and blockers belong in Distribution's Build24 receipt.

The repository source is the durable implementation. A source commit alone
does not update the installed app. Copy only an exactly reviewed and signed
Release app, verify the installed bytes, and retain the prior installed version
when one exists. No unsigned substitute or modified admission is a qualified
installation.
